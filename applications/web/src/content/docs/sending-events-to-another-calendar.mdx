To send events to another calendar, open the calendar the events live in and use **Send Events to Calendars**. Each calendar you tick becomes one connection. Events are copied into it, one way, and the copies are kept corrected as the originals change.

## Turning it on

The **Send Events to Calendars** list holds every calendar Keeper.sh can write to. Tick one and events start flowing. There is no separate screen and no order to get right.

If the calendar you want is not listed, Keeper.sh cannot write to it. A calendar subscribed from a link is the usual case — [linked accounts and calendars](/docs/accounts-and-calendars) covers which calendars can receive events.

## Getting events to travel both ways

A connection copies events into the calendars you ticked and, by default, nothing comes back. There are two different ways to change that, and they are not the same thing.

[Two-way sync](/docs/two-way-sync) makes the copy editable: an edit you make to the copy is written back to the original event, and there is still only one event on each side. It is a Pro feature, you turn it on per connection, and deleting the original is a separate option you have to confirm.

The other way is to set up two connections, one from each calendar's page, so each calendar sends its own events to the other. Think before building that. Every event now exists twice, and each copy is a real event in a real calendar — turning on two-way sync as well means deleting one of those copies can delete a real event. The [sync your work and personal calendars](/recipes/sync-work-and-personal-calendars) recipe walks through a setup that stays readable.

## The copy follows the original

Move the original and the copy moves. Shorten it and the copy shortens. Delete it and the copy is deleted.

That is what separates this from an import. The receiving calendar is corrected in place, so it never collects a fresh copy every time something changes.

Seeing two of something anyway? [the same event appears twice in one calendar](/guides/same-event-appears-twice) covers the setups that cause it.

## How quickly a change lands

On Pro, Google and Outlook tell Keeper.sh when an event changes, so the copy lands within seconds. Otherwise Keeper.sh checks every calendar every minute, and a change reaches your other calendars within 30 minutes on Free, and within a minute on Pro.

Google and Outlook tell Keeper.sh only what changed since last time. Checking stays fast even on a busy calendar. A calendar subscribed from a link has no such shortcut and is read in full each time.

## Removing a connection

Untick the calendar in **Send Events to Calendars** and new events stop being copied. Events already copied stay where they are. Clear them out yourself if you do not want them.
